# DynamoDB
**Date:** Apr 11, 2026  
**Folder:** dynamodb  

---

### Overview

- Fully managed NoSQL database — schemaless, supports structured/semi-structured/unstructured data
- Millisecond latency, handles all traffic levels
- Data replicated across multiple AZs on SSDs, built-in encryption at rest

### Table Structure

- **Tables** → **Items** (rows) → **Attributes** (columns, can vary per item)
- **Partition Key (simple)**: single unique attribute (hash)
- **Composite Key**: partition key + sort key (range)

### Secondary Indexes

- **LSI**: same partition key, different sort key — created at table creation, max 5
- **GSI**: different partition and sort keys — can add/modify after creation

### DynamoDB Streams

- Captures all writes in real-time (insert, update, delete)
- 24-hour retention; view options: Keys Only / New Image / Old Image / Both
- Use cases: Lambda triggers, S3/Redshift pipelines, cross-region replication

### DynamoDB Accelerator (DAX)

- In-memory cache, microsecond latency, up to 10x improvement
- Write-through: writes go to DynamoDB first, then cache

### Capacity Modes

- **On-Demand**: pay per request, never throttles, ~2x premium
- **Provisioned**: specify RCU/WCU, auto-scaling available, more cost-effective
- **WCU**: 1 write/sec for items ≤1KB
- **RCU**: 1 strongly consistent read/sec (4KB) or 2 eventually consistent

### Performance

- Hot partitions: uneven distribution → bottlenecks
- Solutions: balanced keys, exponential backoff, DAX for reads
- **Burst Capacity**: unused capacity accumulated for 5 min
- **Adaptive Capacity**: auto-redistribute throughput

### Time To Live (TTL)

- Auto-delete items by Unix epoch timestamp
- 48-hour deletion window; no WCU consumed; captured in Streams if enabled
